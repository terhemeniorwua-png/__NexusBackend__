# Teams & Projects API Audit

**Branch:** `feat/teams-projects-gap-api`  
**Scope:** Read-only Phase 1 audit of Team management and Project management against the requested checklist. Evidence gathered from `prisma/schema.prisma`, `src/modules/teams/*`, `src/modules/projects/*`, `src/modules/workspaces/*`, `src/modules/authorization/*`, `src/modules/tasks/*`, routes/services/schemas/types, and existing tests. No code behavior changed in Phase 1.

**Status legend**
- **COMPLETE:** data model + relevant CRUD/read behavior + server-side authorization + validation + at least one test (verified by code inspection).
- **PARTIAL:** implemented in part but missing one or more required elements (model/API/auth/validation/test/behavior).
- **MISSING:** not implemented.

## Phase 1 conclusion
The codebase has substantial team and project foundations (models, core CRUD/member/milestone/archive/activity primitives, authorization policies, audit logging, and existing tests), but several checklist requirements are **PARTIAL** or **MISSING**—notably case-insensitive unique team names, bulk/lead/multi-lead/team-overview/activity responsibilities, project objectives (structured), multi-team association, bulk add by team, milestone-task linkage/progress, project progress endpoint, and completion/archive workflow details (open-task handling, timestamps/actor persistence, notifications, consistent read-only enforcement). Phase 2 should address these gaps additively while preserving existing behavior.

### Cross-cutting notes (Phase 2)
- **Pagination:** added cursor pagination for team activity feed (`nextCursor`); project list/activity/progress-related feeds remain cursor-based as before. Team/member/milestone list endpoints still return arrays (unchanged contracts) except where new feed semantics apply.
- **Indexes:** added case-insensitive partial unique index for non-deleted team names, `ProjectTeam` unique/indexes, `Task.milestoneId` indexes, and project completion/archive indexes/FKs in additive migration.
- **Audit/activity:** all new mutations emit audit records; team project link/unlink events emitted (`team.project_linked`, `team.project_unlinked`) and surfaced in team activity feed. Project complete/archive/restore/member removal now emit notifications where appropriate.
- **Workspace isolation/auth/validation/tests:** new endpoints are authenticated (`requireAuth`), require active account (`requireActiveAccount`), workspace-scoped via existing authorization checks, validated with zod `.strict()` schemas, and covered by new schema/unit tests plus existing relevant unit/integration-style tests that pass in this environment.
- **Soft/hard delete consistency:** preserved existing behavior (teams/projects soft-deleted as before; milestone hard delete unchanged).
- **Not fully addressed (deliberately/minimally changed):** explicit team-level visibility field not added; comment policy end-to-end enforcement across all comment surfaces was not exhaustively refactored (existing authorization hooks retained); project create-from-template remains available via existing template endpoint rather than duplicating flow in main create; archived read-only enforcement relies on existing project authorization/update guards and may need a broader pass for every possible surface.
